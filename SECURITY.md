# Security reporting

Do not put credentials, precise sensitive locations, personal data, or exploit details in public Issues. Use a repository private vulnerability report only if that feature is available, or the real private contact after it is configured. The development placeholder cannot receive reports.

No real organization dataset is published during this development stage. All code/data changes require source and safety review before release. If sensitive material enters public history, current-file deletion alone is insufficient: assess history cleanup, hosting/cache removal, affected joined exports, and safe recovery.

请勿在公开 Issue 发布凭证、敏感地点、个人资料或漏洞利用细节。开发占位联系方式无法接收报告；真实私密渠道必须在正式发布前配置。
